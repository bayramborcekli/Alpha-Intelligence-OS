MISSION — WINDOWS BACKGROUND SERVICE BOOTSTRAP (PARITY WITH GUNICORN)

AMAÇ:
Windows sürümünde Gunicorn post_fork tarafından başlatılan arka plan servislerini güvenli şekilde başlatarak Linux/Replit ile aynı runtime mimarisini sağla.

ÖNEMLİ:
Bu görev yeni özellik eklemek değildir.
Bu görev yalnız Windows başlatma zincirini tamamlar.

KESİN KÖK NEDEN:

Linux:

gunicorn post_fork
    ↓
start_auto_loop()
start_controller_loop()
start_automation_scheduler()

Windows:

serve_windows.py
    ↓
waitress.serve(...)
    ↓
BİTER

Sonuç:
- auto_controller thread yok
- automation_scheduler thread yok
- universe_manager thread yok
- _run_single_cycle() hiç çalışmıyor

YAPILACAKLAR:

1)

gunicorn.conf.py post_fork() içinde başlatılan servisleri incele.

Listele:

- start_auto_loop()
- start_controller_loop()
- start_automation_scheduler()

Windows tarafında aynı başlatma sırasını oluştur.

2)

serve_windows.py

waitress başlamadan önce veya güvenli bootstrap noktasında

Linux ile aynı servisleri başlat.

Başlatma sırası Linux ile aynı olsun.

3)

Koruma ekle.

Threadler ikinci kez oluşturulmasın.

Tek instance kuralı:

- aynı thread zaten çalışıyorsa tekrar başlatma
- restart güvenli olsun
- çift scheduler oluşmasın

4)

Config davranışını DEĞİŞTİRME.

Aşağıdakilere DOKUNMA:

adaptive_system.enabled
kill_switch
auto_paper_enabled
mode
ALPHA_AUTOMATION_ENABLED

Servisler yalnız mevcut ayarlara göre davransın.

Bu görev otomasyonu açmaz.

Sadece başlatma zincirini tamamlar.

5)

Log ekle.

Windows başlangıcında açıkça görülsün:

AUTO LOOP STARTED
CONTROLLER STARTED
AUTOMATION SCHEDULER STARTED

veya

CONTROLLER DISABLED (enabled=false)
SCHEDULER DISABLED
AUTO LOOP DISABLED

Sebep de yazılsın.

6)

Runtime doğrulaması.

Windows açıldıktan sonra raporla:

- auto_controller thread durumu
- automation_scheduler thread durumu
- universe_manager thread durumu

- thread id
- alive=True/False
- başlatılma zamanı

7)

KESİNLİKLE DOKUNMA:

- Binance
- Paper Ledger
- Position Management
- Trading Logic
- Dashboard
- Auth
- Session
- Executive API
- Risk Engine

TESTLER:

A)
Windows

Uygulama açılır.

Threadler Linux ile aynı bootstrap sırasıyla oluşturulur.

B)

enabled=false ise

Thread başlatılmaya çalışılır ancak uygun "disabled" logu üretilir.

Exception oluşmaz.

C)

Restart

İkinci scheduler oluşmaz.

İkinci controller oluşmaz.

D)

Linux/Replit

Davranış tamamen korunur.

E)

Panel çalışmaya devam eder.

HTTP 500 oluşmaz.

ÇIKTI:

- Değişen dosyalar
- Başlatma sırası
- Yeni log çıktıları
- Thread durumları
- Windows/Linux davranış karşılaştırması
- Tek commit

NOT:

Bu görevin amacı Paper otomasyonunu aktif etmek değildir.

Amaç yalnız Windows'un Linux ile aynı servis başlatma mimarisine kavuşmasıdır.

Config bayrakları (enabled, kill_switch, mode, auto_paper_enabled) sonraki görevde ayrıca ele alınacaktır.
