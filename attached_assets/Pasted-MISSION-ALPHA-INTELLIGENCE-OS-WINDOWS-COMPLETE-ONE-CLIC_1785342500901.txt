Windows kullanıcısı yalnızca tek dosyayı çalıştıracak:

- Windows ortamını hazırlar

- Python/.venv kurulumunu tamamlar
- .env dosyasını güvenli biçimde oluşturur veya onarır

- isteğe bağlı Binance Global/TR read-only hesap bağlantısını kurar
- dashboard Runtime kartını yeşile getirir
- tek FINAL PASS/FAIL raporu üretir

ARTIK PARÇALI BETİK, İKİNCİ ÇALIŞTIRMA, AYRI TEŞHİS KOMUTU VEYA KULLANICIYI DOSYA DÜZENLEMEYE YÖNLENDİRME YOK.

============================================================
1. TEK GİRİŞ NOKTASI
============================================================

Yeni tek Windows giriş dosyası:

SETUP_AND_START_WINDOWS.cmd

Gerekli karmaşık işlemler için arka planda:

windows_setup.ps1

kullanılabilir.

Kullanıcı yalnız SETUP_AND_START_WINDOWS.cmd dosyasına çift tıklayacak.

Mevcut:

- INSTALL_WINDOWS.cmd
- RECOVER_WINDOWS.cmd
- windows_diagnose.py
- start_alpha.cmd

işlevleri bu tek akış altında birleştirilecek.

Eski dosyalar gerekiyorsa uyumluluk yönlendirmesi olarak kalabilir, fakat kullanıcıya ayrı ayrı çalıştırılmayacak.

============================================================
2. GIT OTOMATİK KURULUM VE GÜNCELLEME
============================================================

Önce Git’i ara:

- PATH içindeki git.exe
- C:\Program Files\Git\cmd\git.exe
- C:\Program Files (x86)\Git\cmd\git.exe
- GitHub Desktop içindeki Git

Git bulunursa tam yolu kullan.

Git bulunmazsa:

- winget mevcutsa Git.Git paketini otomatik kur
- gerekli kullanıcı/yönetici onayını göster
- kurulumdan sonra PATH yeniden yüklenemiyorsa Git’in tam yolunu doğrudan kullan
- kullanıcının terminali kapatıp açmasını isteme

Sonra:

- aktif branch’i doğrula
- git status kontrol et
- kullanıcıya ait takip edilmeyen .env/state/runtime dosyalarını koru
- güvenliyse git pull yap
- HEAD commit’i kaydet

Çalışma ağacında kaynak kod değişikliği varsa üzerine yazma; açık ve tek hata göster.

============================================================
4. .ENV GÜVENLİ OTOMATİK ONARIM
============================================================

Runtime yalnız gerçek .env dosyasını kullanacak.

.env.example hiçbir zaman runtime dosyası kabul edilmeyecek.

.env yoksa oluştur.

.env varsa:

- silme
- önce .env.backup_<timestamp> yedeği al
- mevcut parola/hash/session/Binance değerlerini koru
- duplicate satırları güvenli biçimde normalize et

Aşağıdaki yerel ayarları garanti et:

FLASK_ENV=development
LOCAL_DEV_BYPASS=1
PAPER_MODE=true
ALPHA_WINDOWS_PAPER_AUTO=true

SESSION_SECRET veya FLASK_SECRET_KEY yoksa:

- güvenli rastgele değer üret
- yalnız .env dosyasına yaz
- terminale secret değerini basma

Kesinlikle:

- .env Git’e eklenmeyecek
- .env.example içine gerçek secret yazılmayacak
- ALPHA_ENABLE_LIVE_TRADING açılmayacak

Onarım için kullanıcıdan ikinci çalıştırma isteme.
Onarım sonrası aynı akış devam etsin.

============================================================
5. WINDOWS SSL/TLS VE BINANCE PUBLIC DATA
============================================================

Uygulama import edilmeden önce:

truststore.inject_into_ssl()

aktif olsun.

SSL doğrulaması her zaman açık kalacak.

KESİNLİKLE YASAK:

- verify=False
- CERT_NONE
- sertifika doğrulamasını kapatma

Test et:

- https://fapi.binance.com
- BTCUSDT kline
- ETHUSDT kline
- SOLUSDT kline

Her endpoint için:

- en az 5 deneme
- artan bekleme
- her denemede temiz bağlantı/session
- PASS sayısı ve hata tipi

Geçici TLS hataları tek sembol yüzünden sistemi tamamen durdurmamalı.

En az iki sembol veri verebiliyorsa controller başlatılmalı ve problemli sembol geçici olarak atlanmalı.

Tüm semboller başarısızsa gerçek nedeni sınıflandır:

- CERTIFICATE_VERIFY_FAILED
- SEC_E_INVALID_TOKEN
- TLS alert
- timeout
- DNS
- proxy/VPN
- antivirüs HTTPS inspection

Kodla güvenli biçimde düzeltilemeyen makine ayarında yalnız tek açık kullanıcı işlemi göster.

============================================================
6. DAYANIKLI MARKET DATA DAVRANIŞI
============================================================

Public kline isteklerinde:

- retry
- exponential backoff
- timeout
- geçici sembol izolasyonu

bulunsun.

Bir sembolün geçici SSL/ağ hatası:

- controller thread’ini öldürmemeli
- tüm cycle’ı kalıcı durdurmamalı
- diğer sembollerin analizine engel olmamalı

429/418 durumunda mevcut rate-limit güvenliği korunmalı.
