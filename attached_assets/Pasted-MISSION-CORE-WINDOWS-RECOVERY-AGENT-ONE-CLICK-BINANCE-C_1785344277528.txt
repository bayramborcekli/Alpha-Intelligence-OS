MISSION — CORE WINDOWS RECOVERY AGENT + ONE-CLICK BINANCE CONNECTION AGENT

AMAÇ

Daha önce başarıyla çalışan Windows tek tık kurulum/kurtarma çözümünü geçici betik olmaktan çıkarıp Alpha Intelligence OS’un ana agent mimarisine kalıcı olarak işle.

Aynı görev içinde Binance Global ve Binance TR hesap bağlantılarını güvenli, anlaşılır ve tek akışlı bir yerel bağlantı sihirbazıyla tamamla.

Bu görev iki kalıcı sistem agentı oluşturacak:

1. Windows Runtime Recovery Agent
2. Binance Connection Agent

Parçalı görev, manuel .env düzenleme, terminalden çoklu komut veya ayrı bağlantı betikleri olmayacak.

============================================================
1) ANA SİSTEM AGENT MİMARİSİ
============================================================

Önce mevcut repository mimarisini incele.

Mevcut bir agent registry/manager yapısı varsa onu kullan.
Yoksa minimum ve sade bir registry oluştur:

alpha_agents/
    __init__.py
    registry.py
    windows_runtime_agent.py
    binance_connection_agent.py

Agentlar uygulamanın ana sistemi tarafından tanınmalı ve durumları dashboard üzerinden görüntülenebilmelidir.

Registry en az şu bilgileri vermeli:

- agent_id
- agent_name
- enabled
- status
- last_run
- last_result
- last_error
- capabilities

Agentlar uygulama import edilirken ağır işlem başlatmamalı.
Yalnız açıkça çağrıldığında çalışmalı.

2) WINDOWS RUNTIME RECOVERY AGENT
============================================================

Daha önce başarıyla çalışan şu dosyaları yeniden yazma veya bozma:

- SETUP_AND_START_WINDOWS.cmd
- windows_setup.ps1
- windows_setup_flow.py
- serve_windows.py
- windows_diagnose.py
- RECOVER_WINDOWS.cmd
- INSTALL_WINDOWS.cmd

Mevcut çalışan akışı Windows Runtime Recovery Agent içine bağla.

Agent şu yeteneklere sahip olsun:

- Git bulma/kurma/güncelleme
- Python ve .venv hazırlama
- requirements kurulumu
- certifi/truststore hazırlama
- .env güvenli onarımı
- Binance public veri kontrolü
- yalnız Alpha süreçlerini kapatma
- serve_windows.py başlatma
- /health/runtime doğrulama
- Paper AUTO/controller başlatma
- FINAL PASS/FAIL raporu

Agent yeni mantık icat etmemeli.
Başarılı olduğu kanıtlanan mevcut akışı reusable servis olarak çağırmalı.

Tek kaynak prensibi uygula:

- CLI betikleri
- dashboard
- agent registry

aynı Python recovery servislerini kullanmalı.

Kod tekrarını azalt.

Önerilen ortak servis:

services/windows_runtime_recovery.py

Buraya windows_setup_flow.py içindeki tekrar kullanılabilir fonksiyonlar güvenli biçimde ayrılabilir.

Ancak mevcut çalışan:

SETUP_AND_START_WINDOWS.cmd

davranışı kesinlikle bozulmayacak.

============================================================
8) BINANCE GLOBAL BAĞLANTI TESTİ
============================================================

Binance Global bağlantısında sırasıyla:

1. DNS/TLS/public endpoint testi
2. server time alma
3. yerel saat ile Binance saati farkını ölçme
4. timestamp offset hesaplama
5. imzalı read-only account sorgusu
6. izin alanlarını kontrol etme
7. hesap tipini doğrulama
8. Futures hesabı varsa ayrı durum olarak belirleme

Şu hataları ayrı sınıflandır:

- API_KEY_INVALID
- API_SECRET_INVALID
- IP_RESTRICTED
- PERMISSION_DENIED
- TIMESTAMP_DRIFT
- REGION_RESTRICTED
- TLS_ERROR
- DNS_ERROR
- RATE_LIMIT
- TEMPORARY_NETWORK_ERROR
- UNKNOWN_RESPONSE

Timestamp hatasında kullanıcıyı hemen reddetme.

Önce Binance server time üzerinden otomatik offset kullanarak tekrar dene.

TLS/geçici bağlantı hatasında:

- 5 deneme
- exponential backoff
- her denemede yeni session
- SSL doğrulaması açık

Kesinlikle kullanma:

- verify=False
- CERT_NONE

============================================================
9) BINANCE GLOBAL İZİN GÜVENLİĞİ
============================================================

Global hesap cevabında mevcutsa kontrol et:

- canTrade
- canWithdraw
- canDeposit
- brokered
- permissions
- accountType

Politika:

- canWithdraw=true ise bağlantıyı REDDET
- withdrawal yetkisi açık anahtar saklanmasın
- canTrade=true ise açık ve kırmızı uyarı göster

Sistem yalnız salt okunur bağlantı hedefliyorsa:

- trading yetkisi açık anahtarı varsayılan olarak reddet
- kullanıcıya Binance panelinden trading/withdrawal yetkilerini kapatmasını söyle
- anahtarı güvenli depoya kaydetme

Read-only olduğu doğrulanan bağlantı:

CONNECTED_READ_ONLY

olarak işaretlensin.

Yetki alanları API tarafından kesin doğrulanamıyorsa:

CONNECTED_PERMISSIONS_UNVERIFIED

olarak sarı durumda gösterilsin.

Yanlış biçimde tam güvenli görünümü verme.
