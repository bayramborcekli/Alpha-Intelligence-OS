MISSION OBJECTIVE

Transform the current fragmented monitoring-oriented dashboard into a
controlled trading operations workspace where the operator can:

- See every product currently managed by the system.

- See realized and unrealized profit/loss.

  authorized by the certified execution controls.

- Keep all LIVE functionality fail-closed.

CONTROLLED AUTOMATIC TRADING

The system may perform automatic trading only when all conditions are true:

- Automation state is RUNNING.
- Execution mode permits the requested operation.
- An eligible strategy candidate exists.
- Strategy output has been normalized into a controlled execution intent.
- Authorization is valid.
- Permission gate returns PASS.
- Risk engine returns PASS.
- Kill switch is inactive.
- Symbol automation is enabled.
- Cooldown and exposure limits pass.
- Idempotency check passes.
- Ledger and lifecycle services are available.
- Reconciliation is not in a policy-defined blocking state.

Any unknown, missing or stale safety dependency must deny execution.

No fail-open behavior is allowed.

DEFAULT MODE

On a clean installation or unknown configuration:

- Execution mode = PAPER
- Automatic trading = STOPPED
- Live order authorization = DENIED
- Symbol automation = DISABLED
- Close-all live action = DENIED
- Exchange write = 0

The UI must never infer LIVE readiness from exchange connectivity alone.

A connected API key does not mean live authorization exists.
