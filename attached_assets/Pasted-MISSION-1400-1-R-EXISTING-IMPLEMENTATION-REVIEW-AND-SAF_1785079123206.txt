PHASE 2 — ARCHITECTURE DECISION

The current application may use either:

A. Environment-based owner credentials:
- ALPHA_OWNER_USERNAME
- ALPHA_OWNER_PASSWORD_HASH

or

B. First-run owner setup wizard with server-side password hash storage.

Do not implement both systems simultaneously.

If the current first-run setup wizard is secure and already working, preserve it
and document it as the chosen single-owner authentication model.

The setup wizard is acceptable only if:

- it is available only while no owner account exists
- it cannot be reopened after setup
- it never stores plaintext passwords
- it uses Argon2id or bcrypt
- it stores the hash server-side only
- setup requests are CSRF protected where applicable
- setup is rate limited
- setup state fails closed
- owner data is persistent across application restarts
- the database or persistence file is excluded from Git
- there is no default username or default password
- logs and API responses never expose the hash
- deleting cookies does not reopen setup
- concurrent setup attempts cannot create multiple owners

If any of these conditions fail, repair the existing setup wizard rather than
adding a second authentication system.

SESSION_SECRET must remain required through environment configuration.
