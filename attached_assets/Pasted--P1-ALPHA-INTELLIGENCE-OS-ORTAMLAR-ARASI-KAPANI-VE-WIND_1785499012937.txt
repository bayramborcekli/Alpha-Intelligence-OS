# P1 — ALPHA INTELLIGENCE OS ORTAMLAR ARASI KAPANIŞ VE WINDOWS KÖK NEDEN AGENTI

## Rolün

Sen bu görevde Alpha Intelligence OS için kıdemli tanılama ve güvenlik agentısın.

Amacın:

1. Replit’te düzeltilmiş piyasa-veri akışının bozulmadan kaldığını doğrulamak.
2. Windows’taki benzer ekran belirtisinin gerçek kök nedenini bağımsız olarak kanıtlamak.
3. Binance Global private-auth sorununu public piyasa verisinden kesin biçimde ayırmak.
4. Kanıtlanmamış hiçbir şeyi kod regresyonu, IP sorunu veya scheduler arızası olarak ilan etmemek.
5. Kaynak kodu değiştirmeden önce Executive Review için kesin kök neden raporu teslim etmek.

Bu sprintte NO_SIGNAL Faz 2 geliştirmesine başlama. Altyapı doğrulandıktan sonra Reject Strength, Filter Combination, Recovery ve Dynamic Reject Timeline ayrı görev olacaktır.

---

## 1. Kabul edilmiş mevcut durum

### Replit — çözülmüş ve korunacak

31 Temmuz 2026 tarihli son doğrulamada:

```text
PUBLIC_MARKET_DATA: PASS
PIPELINE: GREEN
ANALYSIS_SCHEDULER: RUNNING
SCAN_INTERVAL: 5 dakika
UNIVERSE: 4 sembol
RUNTIME_CORE_COUNT: 10
RUNTIME_OPPORTUNITY_COUNT: 20
NOT_RUN_YET: TEMİZLENDİ
COIN_NAMES_AND_PRICES: GÖRÜNÜR
GLOBAL_PAUSE: ACTIVE
LIVE_ORDERS: DISABLED
OPEN_LIVE_POSITIONS: 0
EXCHANGE_WRITE_REQUESTS: 0
```

Kanıtlanmış Replit kök nedeni iki halkalıydı:

```text
Kanonik operasyon durumu STOPPED
+
adaptive engine enabled=false
→ scheduler çalışmıyor
→ evren yenilenmiyor
→ NOT_RUN_YET
→ fiyat ve analiz ekranı boş
```

Bunlar kanonik uygulama uçlarıyla düzeltildi:

```text
POST /api/operation-control/automation/start
/adaptive/enable
```

Kaynak kod değiştirilmedi. Ancak operasyonel durum değişti:

```text
operation store → RUNNING
config.json → adaptive enabled=true
runtime store’lar → yenilendi
```

Replit’te bu ayarları yeniden değiştirme, durdurma veya yeniden başlatma. Restart ancak yeni ve kanıtlanmış bir zorunluluk varsa değerlendirilir.

### Replit scheduler rozeti

Bir ekran görüntüsünde geçici olarak `STARTUP_FAILED` görülmüş, sonraki ekranda:

```text
Analiz Zamanlayıcısı: RUNNING
Pipeline: GREEN
Son Analiz: taze
```

görülerek düzelmiştir.

Bu nedenle `STARTUP_FAILED` şu anda aktif kök neden değildir. Yalnız tekrarlanabilir ve backend durumuyla çelişen yeni kanıt varsa Görev 116 kapsamındaki çoklu Gunicorn worker/süreç-yerel rozet problemi olarak incele.

### Binance Global private bağlantısı

Replit’te imzalı private istek şu sonucu veriyor:

```text
GET /api/v3/account
HTTP 401
Binance code: -2015
AUTH_FAILED
```

Kesin kanıt yalnız şudur:

> Binance etkin anahtarı, IP’yi veya izin kombinasyonunu private hesap isteği için kabul etmiyor.

Aşağıdakiler olasıdır fakat henüz ayrı ayrı kanıtlanmamıştır:

* IP kısıtlaması
* Eski/yanlış API anahtarı
* Anahtarın silinmiş veya yenilenmiş olması
* `Enable Reading` izninin bulunmaması

Private-auth hatası public piyasa verisinin çalışmadığı anlamına gelmez. Replit public fiyat ve tarama akışı hâlen PASS kabul edilmektedir.

### Git durumu

Son bilinen durum:

```text
RUNNING_HEAD: eee5b0a
origin/main: 687a6e9
```

`eee5b0a`, platformun otomatik checkpoint/auto-commit işlemidir.

Bu görevde:

* Rollback yapma.
* Commit oluşturma.
* Push yapma.
* `eee5b0a` commit’ini silme veya yeniden yazma.
* Unrelated dosyalara dokunma.

## 5. FAZ C — Güvenli Windows teşhis tasarımı

Windows’a doğrudan erişimin yoksa, kullanıcıya çalıştırılmak üzere tek parça PowerShell teşhis metni hazırla ve:

```text
RESULT: BLOCKED
WAITING_FOR: WINDOWS_DIAGNOSTIC_OUTPUT
```

olarak dur.

Yeni teşhis aşağıdaki şartları sağlamalıdır:

### Yasaklar

* `import app` kullanma.
* `import dual_model` kullanma.
* Uygulama modüllerini çalıştırma.
* Runtime/config/state dosyalarına yazma.
* `/api/dual-model/state` çağrısını, route’un salt-okunurluğu kanıtlanmadan yapma.
* Ham log dosyalarını dökme.
* Ham process command line yazdırma.
* Env değerlerini veya secret uzunluklarını dahi gereksiz yere gösterme.
* Servisi başlatma, durdurma veya restart etme.
* Runtime dosyalarını silme/yeniden oluşturma.
* Sistem Python’unu kullanma.

### Kullanılacak Windows çalışma düzeni

Önce doğrula:

```text
PROJECT_ROOT
PROJECT_ROOT\.venv\Scripts\python.exe
PROJECT_ROOT\serve_windows.py
```

Python sürümü ve çalıştırıcı yolu açıkça raporlansın. Sistem Python’u yerine proje `.venv` Python’u kullanılmalıdır.

Portlar süreç üzerinden güvenli biçimde belirlenemiyorsa yalnız beklenen yerel portlar kontrol edilebilir:

```text
5000
8080
```

Ancak herhangi bir HTTP endpoint’ini çağırmadan önce route’un GET sırasında yazma, dış ağ veya hesap senkronu yan etkisi oluşturmadığını kaynak koddan doğrula.

### Modül yolları

Modül yolunu bulmak gerekiyorsa modülü çalıştırmadan statik çözüm kullan.

Yeni teşhis sürecinde bulunan yollar şu şekilde adlandırılmalı:

```text
DIAGNOSTIC_APP_PATH
DIAGNOSTIC_DUAL_MODEL_PATH
```

Bunları aşağıdaki gibi adlandırma:

```text
RUNNING_IMPORTED_APP_PATH
RUNNING_IMPORTED_DUAL_MODEL_PATH
```

Çalışan sunucunun gerçek import yolları bağımsız kanıtlanamıyorsa açıkça:

```text
RUNNING_IMPORT_PATHS: UNVERIFIED
```

yaz.

### Süreç bilgisi

Yalnız güvenli alanları göster:

* PID
* Executable path
* Working directory, güvenli biçimde alınabiliyorsa
* Dinlenen yerel port
* Başlangıç zamanı

Command line gerekiyorsa tüm anahtar, secret, token, URL credential ve env değerleri kesin redaksiyondan geçirilmelidir. Güvenilir redaksiyon yapılamıyorsa command line hiç gösterilmemelidir.

### Dosya bütünlüğü

Hazırlanan teşhis betiği için teslim et:

```text
FILE_SIZE:
SHA256:
WRITE_COMMANDS_FOUND:
MODULE_IMPORT_SIDE_EFFECTS:
HTTP_SIDE_EFFECT_REVIEW:
SECRET_OUTPUT_REVIEW:
```

Betik kendi oluşturulması dışında hiçbir proje/runtime dosyasını değiştirmemelidir.

## 6. FAZ D — Windows kök neden ayrımı

Windows’ta aşağıdaki zincirleri birbirinden ayrı değerlendir:

### 1. Sunucu/başlatıcı

* Sunucu gerçekten çalışıyor mu?
* `start_alpha.cmd` PowerShell altında sessizce dönüyor mu?
* `.venv\Scripts\python.exe` mi kullanılıyor?
* `serve_windows.py` mı başlatılıyor?
* Port 5000/8080 üzerinde beklenen süreç var mı?
* Duplicate instance veya eski PID var mı?
* PID tracking doğru mu?
* Görünür hata/log mekanizması çalışıyor mu?

### 2. Public Binance piyasa verisi

Secret kullanmadan public endpoint düzeyinde değerlendir:

* DNS
* TLS
* Binance Global public ping/time
* Public ticker/klines
* HTTP durum kodu
* Yanıt gövdesi ve hata sınıfı
* Uygulamanın kullandığı gerçek base URL

Public veri çalışıyorsa bunu private-auth durumundan ayrı `PASS` yaz.

### 3. Private Binance Global auth

Yalnız mevcut uygulamanın zaten yapılandırılmış, salt-okunur kimlik yolunu ve güvenli durum özetini incele.

* Secret’ı çıkarma.
* Windows DPAPI secret’ını çözerek raporlama.
* Anahtarı Replit anahtarıyla aynı kabul etme.
* Windows ve Replit’in farklı credential source kullanabileceğini dikkate al.
* `-2015` alınırsa IP kısıtı olduğunu kanıtsız kesinleştirme.
* İmzalı test yapılacaksa yalnız salt-okunur hesap endpoint’i kullanılmalı ve secret hiçbir çıktıya girmemeli.

### 4. Scheduler/operation state

Windows’ta Replit kök nedenini varsayma. Bağımsız doğrula:

* Operation state
* Adaptive enabled
* Controller
* Scheduler
* Son analiz
* Scheduler refresh
* Universe status
* Runtime dosyasının tazeliği
* CORE/OPPORTUNITY sayıları
* UI/API/runtime tutarlılığı

Aynı ekran belirtisi, aynı kök neden anlamına gelmez.

## 7. FAZ E — Binance operatör işlemini doğru sınırla

Agent Binance hesabında anahtar oluşturamaz veya izin değiştiremez.

Replit `AUTH_FAILED (-2015)` için kullanıcıya yalnız şu güvenli operatör sınırını raporla:

```text
Ayrı bir Binance Global API anahtarı kullanılmalı.
Yalnız Enable Reading açık olmalı.
Spot/Futures Trading kapalı olmalı.
Withdraw kapalı olmalı.
Anahtar ve secret rapora/loga yazılmamalı.
```

IP kısıtını kaldırmayı otomatik çözüm olarak önermeden önce anahtarın yalnız-okuma olduğundan emin olunmalıdır.

Trading veya Withdraw yetkili bir anahtarda IP kısıtının kaldırılmasını önerme.

Yeni anahtar hazır değilse:

```text
BINANCE_GLOBAL_PRIVATE_AUTH: OPERATOR_ACTION_REQUIRED
```

yaz. Bu durum public piyasa verisi için `FAIL` sayılmaz.
