────────────────────────────────────────
12. IDEMPOTENCY CONTRACT

Every state-changing broker operation SHALL require an idempotency key.

State-changing operations include:

• submit_order
• cancel_order

The interface SHALL reject missing or invalid idempotency context before any
future broker implementation performs I/O.

Rules:

• Caller owns the idempotency key.
• Adapter never invents the key.
• Same logical request + same key must represent the same operation.
• Reuse of one key for conflicting operations is forbidden.
• No hidden retry may create a new key.
• No adapter may silently submit twice.

Agent 05 defines the contract only.

Persistence and distributed idempotency storage are deferred.

• order not found

• market closed

Programming and contract violations MAY raise canonical local exceptions.

No native broker status may escape the adapter boundary.

18. BALANCE CONTRACT

BrokerBalance SHALL distinguish:

• total
• available
• reserved
• currency

Unknown values SHALL remain None.

Unknown values SHALL never be treated as zero.

Financial fields SHALL use Decimal.

Invariant examples:

• total cannot be negative unless explicitly supported by account semantics
• available cannot exceed total where both are known
• reserved cannot be negative
• currency cannot be blank

Do not implement currency conversion.

• broker SDK contamination

────────────────────────────────────────
20. RETRY OWNERSHIP

BrokerAdapter SHALL NOT implement generic retry policy.

No automatic retry loops.

No exponential backoff.

No sleep.

No scheduler.

No retry counter generated internally.

Retry orchestration belongs to Execution Service or a future resilience layer.

Concrete adapters SHALL only classify failures accurately, for example:

TEMPORARY_FAILURE

PERMANENT_FAILURE

RATE_LIMITED

This prevents duplicate orders and hidden side effects.

────────────────────────────────────────
21. CANCELLATION SEMANTICS

Cancel operations SHALL be explicit and idempotent.

The interface SHALL distinguish:

• cancellation accepted
• already cancelled
• already filled
• order not found
• cancellation unsupported
• temporary cancellation failure

Do not collapse all outcomes into bool.

The adapter SHALL never claim an order was cancelled without a canonical
normalized result supporting that conclusion.
