MISSION 2300 — AGENT 04

TRADING HOME VISUAL MIGRATION

ROLE

Redesign the existing Trading Home page to match the approved reference design.

This is a frontend-only visual migration.

The approved reference is the dark Binance-style Alpha Intelligence dashboard shown by the user.

The reference image is the visual source of truth.

==================================================
PRIMARY OBJECTIVE
==================================================

Transform the current Trading Home into a clean, professional, Binance-style autonomous investment dashboard.

The screen must feel like a finished financial application.

It must NOT feel like:

- an admin panel
- a developer dashboard
- a system health console
- a collection of unrelated cards

The user is the portfolio owner.

The AI manages investments.

The page shows balances, active operations, queued operations and simple AI status.

==================================================
STRICT SCOPE
==================================================

Modify only:

- Trading Home HTML/template
- Trading Home CSS
- Trading Home JavaScript presentation layer
- navigation presentation if required
- frontend tests related to this page

Do NOT modify:

- backend business logic
- API contracts
- database
- automation engine
- risk engine
- portfolio calculations
- execution logic
- ControlledExecutionAPI
- Operation Center functionality
- wallet balance sources
- authentication
- existing safety controls

Use only existing API endpoints and existing data.

Do not fabricate missing data.

UNKNOWN remains UNKNOWN.

==================================================
REFERENCE PRIORITY
==================================================

Follow this visual hierarchy exactly:

1. Thin top portfolio summary bar
2. Horizontal personal-account strip
3. Large active operations table
4. AI status panel on the right
5. Queued operations table
6. Recent activity table
7. Minimal left navigation

Do not introduce new dashboard sections.

==================================================
PAGE SHELL
==================================================

Use a full-height dark application layout.

Structure:

- fixed left sidebar
- fixed or sticky top summary bar
- scrollable main content
- no unnecessary outer margins
- no oversized page title block
- no welcome banner
- no large explanatory paragraph

The page should open directly into useful financial information.

==================================================
COLOR SYSTEM
==================================================

Base background:

- near-black
- dark charcoal panels
- subtle gray separators

Accent:

- Binance-style amber/gold

Status colors:

- green: profit, connected, active, long
- red: loss, disconnected, stopped, short
- amber: advisor mode, preparing, warning
- blue: managed operation status
- gray: unavailable, disconnected, unknown

Avoid:

- bright gradients
- excessive glow
- large colored card backgrounds
- decorative colors without meaning

==================================================
TYPOGRAPHY
==================================================

Use a clean modern sans-serif stack.

Priorities:

- portfolio values: bold
- profit/loss: bold and colored
- section titles: medium weight
- labels: muted gray
- timestamps and metadata: smaller
- no oversized headings

Format all financial values for human readability.

Examples:

9830.331906875032

must display as:

9.830,33 USDT

35094.2

must display as:

35.094,20 TRY

Use tr-TR formatting.

Never display raw floating-point values.

- stale or missing values must show UNKNOWN

LOADING, EMPTY AND ERROR STATES
==================================================

- use subtle skeleton rows
- do not show fake values

- no oversized illustration

- otherwise show UNKNOWN
- connection failure must not display zero balance
- raw backend exceptions must never reach the user

==================================================
ACCESSIBILITY
==================================================

- visible focus states
- semantic tables
- accessible button names
- sufficient contrast
- status must not rely only on color

==================================================
IMPLEMENTATION DISCIPLINE
==================================================

Before coding:

1. Inspect current Trading Home template.
2. Inspect current CSS and JavaScript.
3. Map every reference-design field to an existing endpoint or existing frontend state.
4. Mark any unavailable field as UNKNOWN.
5. Do not create backend work merely to fill a visual field.

During implementation:

- reuse current data loaders
- introduce presentation adapters only where necessary
- centralize number/date formatting
- centralize status-label mapping
- escape all user/API-provided text
- do not duplicate polling loops
- preserve current refresh interval unless there is a frontend-only reason to consolidate it
