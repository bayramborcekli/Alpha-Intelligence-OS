────────────────────────────────────────
7. AUTHENTICATION / AUTHORIZATION

Tüm export endpoint’leri mevcut `_security_gate` ve repository’deki mevcut
yetkilendirme modelini kullanmalıdır.

Zorunlu:

• anonim erişim reddedilir,
• yeni rol veya permission adı icat edilmez,
• export için auth bypass oluşturulmaz,
• export URL’sine token eklenmez,
• dosya adında kullanıcı kontrollü path kullanılmaz.

GET export salt okunur olduğundan repository politikasına göre CSRF
gerektirmeyebilir. Mevcut güvenlik sözleşmesini izle.

────────────────────────────────────────
8. EXPORT DAVRANIŞI

Export çıktısı:

• deterministik,
• UTF-8,
• sabit kolon sıralı,
• sabit alan sıralı,
• sterile,
• tekrar üretilebilir

olmalıdır.

CSV için:

• sabit başlık sırası,
• doğru escaping,
• formula injection koruması,
• newline güvenliği,
• delimiter repository standardına uygunluk

sağlanmalıdır.

`=`, `+`, `-`, `@` ile başlayan kullanıcı veya dış kaynaklı değerlerin
spreadsheet formula olarak yürütülmesine izin verme.

JSON için:

• deterministic key order,
• geçerli Content-Type,
• secret-free payload,
• minimum veri

sağlanmalıdır.

────────────────────────────────────────
9. HTTP SÖZLEŞMESİ

Repository standardına uygun olarak:

• 200 — export başarılı
• 400 — geçersiz format
• 401 — authentication yok
• 403 — yetki reddi
• 404 — desteklenmeyen export yüzeyi
• 503 — automation status kaynağı kullanılamıyor
• 500 — sterile export error

kullanılabilir.

Gerçek proje standardı farklıysa mevcut standardı koru.

Response header’ları:

• doğru Content-Type
• güvenli Content-Disposition
• Cache-Control: no-store, private
• X-Content-Type-Options: nosniff

mevcut uygulama modeli destekliyorsa eklenmelidir.

Dosya adı statik veya sunucu tarafından güvenli biçimde üretilmelidir.
