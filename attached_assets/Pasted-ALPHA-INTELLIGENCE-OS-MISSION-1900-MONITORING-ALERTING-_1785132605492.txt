6. METRIC DEFINITIONS

Implement only deterministic metrics supported by supplied observations.

Recommendation Count

Total number of recommendation observations.

Evaluated Count

Number of observations containing enough valid information to calculate
an outcome.

Return

For an evaluated observation:

(observed_value - entry_value) / entry_value

Direction handling SHALL be explicit and deterministic:

• INCREASE / BUY-like advisory action:
  positive price movement is positive return

• DECREASE / SELL-like advisory action:
  negative price movement is positive return

• HOLD / NEUTRAL:
  excluded unless Agent 01 explicitly defines an evaluable outcome

Do not invent unsupported action aliases.

Success Rate

successful_evaluated_count / evaluated_count

Return greater than zero = success.

Return equal to zero = neutral, not success.

Average Return

Arithmetic mean of valid recommendation returns.

Maximum Drawdown

Use only supplied peak_value and trough_value:

(peak_value - trough_value) / peak_value

Return the maximum valid drawdown across observations.

Do not reconstruct price history.

Confidence Accuracy

Calculate only when both confidence and outcome are evaluable.

Use a documented deterministic calibration definition.

Preferred bounded definition:

1 - abs(confidence - actual_outcome)

Where:

• confidence is normalized to Decimal range 0–1

• actual_outcome is Decimal("1") for success

• actual_outcome is Decimal("0") otherwise

Average all valid calibration scores.

Do not use machine learning or statistical inference.

7. HEALTH STATUS

Define a closed, deterministic health-status set.

Suggested statuses:

• HEALTHY
• DEGRADED
• CRITICAL
• UNKNOWN

Status evaluation SHALL use named Decimal constants.

No magic numbers inside calculation functions.

The exact thresholds must be documented in code and tests.

A conservative initial rule set may evaluate:

• Data availability
• Evaluated-count coverage
• Success rate
• Maximum drawdown
• Confidence accuracy

Rules SHALL execute in a fixed documented order.

More severe conditions SHALL take precedence.

When insufficient evidence exists:

health_status = "UNKNOWN"

Do not classify unknown data as healthy.

────────────────────────────────────────
9. DETERMINISM

The Core SHALL guarantee:

• Decimal-only arithmetic

• No float calculations

• No random values

• No UUID generation

• No clock access

• No locale-dependent formatting

• Stable recommendation processing order

• Stable limitations order

• Canonical fixed-point numeric strings

• Identical input produces identical output

• No mutation of caller-owned input

• Immutable returned structures

Use only Python standard-library modules unless the repository already
defines an approved immutable-model convention.

────────────────────────────────────────
10. VALIDATION

Reject or safely classify invalid input.

The Core SHALL NOT silently accept:

• float values

• NaN

• Infinity

• negative counts

• zero or negative entry values

• confidence outside the approved range

• malformed fixed-point strings

• unknown action values

• mutable output leakage

Invalid individual observations should not crash the entire report when
they can be represented safely as unevaluated.

Programmer-level envelope violations may raise a sterile domain error.

Never expose raw exception messages.
